# Trading Agent — Phase 1: Data, Features, Strategy, Risk, Backtest

This is the **first working slice** of the full spec — the strategy-testing
core, built and validated before the vision/OCR/RAG layers, because this is
where the 80%-win-rate hypothesis actually gets tested against real
statistical evidence rather than assumed.

## What's real and tested here

- `data/synthetic.py` — generates OHLCV with known regime segments, used to
  validate the pipeline. `data/real_source.py` is a yfinance adapter —
  **not runnable in this sandbox (no network)**, run it on your machine.
- `features/indicators.py` — EMA, RSI, MACD, ATR, Bollinger, ADX, VWAP,
  Donchian, OBV, relative volume. All causal (no lookahead) — verified by
  `tests/test_no_lookahead.py`.
- `features/regime.py` — rules-based regime classifier (strong/weak
  bull/bear, sideways, high/low vol) using ADX + EMA structure.
- `strategy/library.py` — 3 strategies (trend pullback, Bollinger mean
  reversion, Donchian breakout), each requiring **multiple confirming
  conditions**, never a single indicator threshold (per spec Section 3).
- `risk/engine.py` — position sizing, min R:R filter, daily loss limit,
  consecutive-loss circuit breaker, transaction cost + slippage modeling.
- `backtest/engine.py` — bar-by-bar simulation with walk-forward
  train/validation/test split. Metrics: win rate, profit factor, expectancy
  (both $ and R-multiple), max drawdown, per-strategy and per-regime
  breakdowns.
- `tests/` — 9 tests, all passing: metric-correctness tests (hand-computed
  expected values) and lookahead-bias tests (truncated vs. full recompute).

## Run it

```bash
python3 run_backtest_demo.py
```

## What it found (on synthetic data — see caveat below)

Out-of-sample (held-out test split): **50% win rate on 6 trades**,
expectancy +0.62R, profit factor 1.46. Per the spec's own instruction:
**"80% win-rate target not statistically demonstrated."** The system
reports this plainly rather than manufacturing a better-looking number.
Sample size (6 OOS trades) is also far too small to draw any real
conclusion — that's flagged, not hidden.

## Critical caveat

**All results above are on synthetic data**, generated by this same
codebase with hand-picked regime parameters. This validates that the
*pipeline computes correctly* — it says nothing about whether these
specific strategies work on real markets. Next step: run
`data/real_source.py::fetch_yfinance()` locally (network required) and
re-run the backtest on real OHLCV before drawing any real conclusions.
Do not treat the synthetic-data numbers above as evidence about actual
strategy viability.

## Explicitly not built yet

- Vision/OCR chart-parsing pipeline (Section 4) — significant standalone
  CV project, deliberately sequenced after the strategy core is solid.
- RAG knowledge base + retrieval (Sections 2, 15, 16).
- Monte Carlo / parameter sensitivity / bootstrap validation (Section 14
  lists these beyond walk-forward — walk-forward is implemented, the rest
  isn't yet).
- Dashboard, decision journal persistence, live loop (Sections 17, 18, 23).
- Multi-timeframe confluence logic (Section 6) — regime detection currently
  runs on a single timeframe.

## Known simplifications to fix before trusting this further

- `features/indicators.py::vwap()` is cumulative across the whole series,
  not reset per session — flagged in its docstring.
- Regime classifier is rules-based and untuned; thresholds (ADX 25/15,
  vol percentile 80/20) are reasonable defaults, not validated.
- Backtester allows only one open position at a time (matches spec's
  `max_open_positions` default of 1, but is hardcoded in the loop
  structure rather than fully respecting a configured higher value).
